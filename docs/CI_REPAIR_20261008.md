## Causes and repairs

- Unbounded dependencies let clean CI resolve Pandas 3.0.6, scikit-learn
  1.9.1, SciPy 1.18.1 and DuckDB 1.5.6, while the validated local research
  environment used 2.3.1, 1.7.0, 1.16.0 and 1.4.4 respectively. Changed
  timestamp/string/null semantics and removed/deprecated APIs caused errors
  and downstream synthetic-pipeline failures. Supported dependency ceilings
  now reflect the existing protocols; both cold-install jobs use the same
  explicit `.github/constraints-ci.txt` set and record `pip freeze`.
- Reusing an imported UI module in a fresh Streamlit runtime left its
  component unregistered. The shared renderer restores registration only for
  the exact named missing-component error. The shared renderer rethrows unrelated
  API errors; the existing optional theme-probe fallback remains unchanged.
  AppTests now inspect public app session-state keys instead of the removed
  private `filtered_state` attribute. The repaired routes also passed on
  Streamlit 1.65 in an isolated external target.
- The chart candle lookup compared microsecond datetime integers against
  nanosecond timestamp values. It now compares timezone-aware datetimes
  directly; winter/summer tests cover both resolutions and the exact marker
  price.
- Capture tests mixed the original Core schema's `035d9e14…` identity with
  the pinned current schema's `92b4ab17…` identity. Both are now tested
  explicitly, including an exact reconstruction of the original field set.
  Historical stored identities are not rewritten.
- HTF control verification now expands only the explicit 18 later neutral
  defaults omitted from the historical control. Full effective settings still
  must match; active or unknown changes are refused.
- The frozen CatBoost source test now verifies Git's canonical LF bytes while
  accepting Git checkout CRLF conversion. Its original checksum, parameters,
  golden environment and numerical parity remain locked.
- Seed-production refusal checks the persisted authorization before discovering
  Core. Authorized execution uses the verified source resolver rather than
  assuming a sibling folder named `Strategy-Core` exists.

No failed test was disabled and no broad warning suppression was added. Core's
exact dependency commit is unchanged. Existing saved research environments and
approvals retain their original identities.
