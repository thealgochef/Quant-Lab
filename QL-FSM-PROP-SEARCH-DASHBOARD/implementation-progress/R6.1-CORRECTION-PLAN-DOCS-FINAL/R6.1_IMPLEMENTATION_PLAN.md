### A. Context-bar panel: contract, materializer, block, bundle, protocol tightening

**New leaf `features/context_bar_panel_contract.py`** — constants and frozen formula contract:
`PANEL_AS_OF_POLICY_ID_V1 = "completed_bars_last_at_or_before_v1"`; `PanelAsOfPolicy`
(bar_selection `last_completed_bar_close_at_or_before_as_of`, comparator `<=`, same-trading-day
required, consulted partition = the candidate's own partition (train | test) for fold features and
`test_oos_only` for the descriptive artifact, fold tie-break `lowest_fold_index`, partial final bar
`excluded_from_panel`, lookback `prior_completed_bars_same_trading_day_only`, reset
`trading_day_18et_reset_v1`, max staleness = 1 × `panel_interval_seconds`);
`PANEL_AS_OF_POLICY_REGISTRY` (exactly one V1 entry); `PANEL_INTERVALS_SECONDS_V1 = (300, 900)`
(import-time: ⊆ `REPLAY_TIMEFRAMES_SECONDS`); `CONTEXT_BAR_PANEL_FORMULA_VERSION =
"ifvg_context_bar_panel_formula_v1"`; `CONTEXT_BAR_PANEL_MATERIALIZER_VERSION`; `LOOKBACK_BARS = 12`
(interval-relative); **`MINIMUM_SOURCE_BARS = 13`** (the current bar + 12 prior completed bars);
**`STD_DDOF = 0`** (population standard deviation everywhere); `PARTIAL_BAR_POLICY_ID =
"exclude_final_partial_bars_v1"`; `WARMUP_POLICY_ID = "trading_day_lookback_all_features_typed_null_v1"`;
`INTENSITY_SOURCE_FIELD = "volume"`; `SESSION_SCHEME_ID = "ifvg_doc_session_scheme_et_v1"`
(`strategy_core.constants.IFVG_DOC_SESSION_SCHEME`: 18:00 ET boundary; asia 16:00–01:45, london
02:00–07:00, ny 08:00–14:00, closed 17:00–18:00 — always passed explicitly to `classify_session`).

Registered features (owner names, with the intensity source made explicit) and formulas
(Δc_i = close_i − close_{i−1} within the trading day; N = 12; "prior" = bars t−N..t−1; every
window needs 13 completed same-day source bars t−N..t):

| Feature | Family | Formula (ticks; population statistics, ddof = 0) | Categorical |
|---|---|---|---|
| `cbp_realized_range_12` | volatility | mean(high_i − low_i), i ∈ t−N+1..t | no |
| `cbp_realized_volatility_12` | volatility | std(Δc_i), i ∈ t−N+1..t | no |
| `cbp_range_compression_ratio_12` | compression | (high_t − low_t) / mean(range_{t−N..t−1}); zero denominator → formula-NaN, row valid | no |
| `cbp_path_efficiency_12` | trend/path efficiency | \|close_t − close_{t−N}\| / Σ\|Δc_i\|, i ∈ t−N+1..t; zero denominator → NaN | no |
| `cbp_session_state` | session state | `classify_session(bar_close, scheme).session` ∈ {asia, london, ny, none, closed} | **yes** (registered `MISSING_CATEGORY` token) |
| `cbp_volume_intensity_zscore_12` | intensity (source field `volume` = summed 1m volume of the completed bar) | (volume_t − mean(volume_{t−N..t−1})) / std(volume_{t−N..t−1}); zero std → NaN | no |
| `cbp_bar_position_in_session` | session state | (bar_close − session_open) / (session_close − session_open) for the named session of the bar close, clamped to [0, 1]; DST via the scheme tz; early close leaves the value < 1 (no future knowledge); `none`/`closed` → NaN | no |

Rules: completed bars only (`is_final_partial` rows excluded; count on the envelope).
Every one of the 13 source bars must satisfy `observed_1m_count == expected_1m_count`; expected
counts already incorporate registered maintenance, early-close, and scheduled-closure semantics.
If any source bar is incomplete, ALL seven features are null, `cbp_valid=False`,
`cbp_missing_reason="source_bar_incomplete"`, and exact offending bar ids/counts are written to the
validity sidecar. Windows never cross the 18:00 ET trading-day boundary (named-session boundaries do
NOT reset the lookback); contiguity `bar_index_t − bar_index_{t−N} == N` else
`cbp_valid=False, cbp_missing_reason="lookback_window_gap"`; warmup `bar_index < N` → all features
null with `insufficient_trading_day_lookback`. A legitimate formula-NaN from a zero denominator keeps
`cbp_valid=True`; source incompleteness never does. `volume`/`trade_count` columns are REQUIRED.
Prohibited inputs by construction: labels, outcomes, MFE/MAE, resolution, future-session statistics,
post-entry evidence, prop outcomes, and MBP-1 features.

  Because standard MBP-1 rows do not carry `channel_id`, the compiler may use `channel_partition`
  only with a verified publisher/channel map; otherwise the flag expands conservatively to
  `publisher_partition` across the physical partition and may not be narrowed to the flagged
