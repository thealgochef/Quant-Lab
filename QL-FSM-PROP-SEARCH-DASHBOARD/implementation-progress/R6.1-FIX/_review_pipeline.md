### B-01 — MAJOR — The costed evaluation of one `costed_evaluation_id` is published from two different frames (raw child tables vs the persisted projection) whose `strategy_metrics.json` bytes differ; a lawful later run fails S02 as a whole stage

- **Contract:** plan §3.7 ("`EXECUTED_TRADE_TABLE_SCHEMA_V1` is the exact ordered executed-trade projection consumed by costed evaluation and S14"; identical bytes reuse / different bytes fail closed), §3.10 (double-run reuse, identical ids), F-06; kickoff §10 "identity projection / immutable reuse".
- **Where:** `src/alpha_lab/agents/data_infra/ifvg/search/pipeline.py::_stage_s02_replays` (evaluation step after the per-child branch: `if result is not None: metrics = compute_strategy_metrics(result.tables, …)` vs `if metrics is None and evidence is not None: metrics = compute_strategy_metrics({EXECUTED_TRADE: evidence.frame}, …)`), `_reuse_child_with_regime_tables`; `search/executed_trade_table.py::project_executed_trades` (int→float64 ticks, date32 trading day); `search/orchestrator.py::_publish_child_evaluation` (sidecar bytes = `json.dumps(metrics.model_dump(mode="json"))`).
- **What is wrong:** S02 computes the costed evaluation from the RAW child tables for fresh children and for regime-reused children (re-derived `result.tables`), but from the Arrow-round-tripped projection (`evidence.frame`) for a reused child without a persisted evaluation. `trade_stats.trade_list[*].entry_ticks/stop_ticks/risk_ticks` serialize as `80000` from the raw frame and `80000.0` from the projection, so the same `costed_evaluation_id` (core id + cost policy only) gets byte-different `strategy_metrics.json` depending on provenance order. `save_or_reuse_envelope` then refuses with "exists with DIFFERENT sidecar content" — and `_publish_child_evaluation` sits OUTSIDE the per-child containment, so the whole S02 stage fails and the remaining children are left non-terminal (`queued`). The plan's statement that costed evaluation consumes the exact projection is not structurally true: only the reused-without-evaluation branch does.
- **Reproduction (synthetic, executed):** `probe_provenance_drift.py` — run 1: `build_pipeline_fixture(regime_study="candidate")`, cost P1 → 4 children `completed`; run 2: plain fixture (no regime), same store, cost 1.25 → 4 children `reused` (0 replays), `E(P2)` published from the table (`strategy_metrics.json` contains `80000.0`); run 3: regime fixture, same store, cost 1.25 → S02 `failed`: "store entry costed_evaluations/883b3e9b… exists with DIFFERENT sidecar content for 'strategy_metrics.json'"; child rows: one `reused`, three `queued`. - **Minimal resolution:** derive every costed evaluation from ONE canonical frame — the verified persisted projection (after `save_executed_trade_table`, evaluate `load_executed_trade_table(...).frame` in the fresh and regime-reuse paths too), so `costed_evaluation_id → strategy_metrics.json` is provenance-independent; move `_publish_child_evaluation` inside per-child containment (typed REPLAY/INVARIANT child failure, never a half-processed stage); make `test_costed_evaluation_from_the_persisted_projection_equals_the_raw_evaluation` compare the serialized sidecar bytes, not `model_dump` dicts. (Alternative: declare the projection with the raw capture dtypes and refuse int-typed tick frames in `project_executed_trades`; the fixture would then have to be re-typed.)

### B-02 — MEDIUM — `probe_executed_trade_table` reports a corrupt store entry (manifest removed, envelope + sidecar present) as lawful "absent"

- **Contract:** plan §3.8 ("`has_sidecar` returns false only when a verified manifest proves that the sidecar was not produced"; `store_entry_missing` is a typed failure reason), §3.7 ("missing/corrupt evidence creates a typed child-stage failure … never silent omission").

In the regime path with a persisted evaluation, the re-persist hits `save_envelope_immutable`'s `destination.exists()` → `FileExistsError` "immutable search-store entry already exists" — a per-child REPLAY failure with a misleading reason. `has_envelope` shares the blind spot, so the store is inconsistent with itself (read: missing; write: exists).

- **Minimal resolution:** in `_verified_manifest`, raise `store_entry_missing` only when `destination` does not exist; when it exists without a manifest raise a typed corruption reason (`malformed_manifest` or a new registered `manifest_missing_for_existing_entry`); `probe_executed_trade_table` maps only the former to "absent". ### B-03 — MEDIUM — The prior-reports recovery branch of S14 returns the prior attempt's record verbatim: failed children of THIS attempt are re-reported, `children_skipped` of this attempt is discarded, and the record names a table the store no longer holds; S14 then reads REUSED and S15 does not reload tables or reports

Add `executed_trade_tables/<id>` for every `children_evidence` entry and `regime_stratified_reports/<id>` for every `stratified_report_ids` entry to `s15_regime_reload_failures`.
